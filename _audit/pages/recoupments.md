## 2. Summary

NEW is a ~5%-of-the-size rebuild that keeps the smallest possible skeleton — per-artist recoupable rollup, a UFR toggle that stamps `ufr_marked_at`, the 20th-cutoff statement-month rule (which is **exactly parity**, see §4), priority/ready/notes artist meta, add-expense, and prior-year tagging — and drops the two systems that made OLD's page trustworthy. First, the **bank-evidence layer**: OLD renders every figure against what the bank can prove (`recoupState` four states, RECOUP_COUNTED headline, the claim-the-provable band, the unverified chip/filter/dot) and admits statement-born rows only once reviewed (`withoutUnreviewedBankRows`). Cadence *has* the raw infrastructure — `server/lib/bankEvidence.js`, `client/src/utils/recoupState.js`, `BankEvidenceDot.jsx`, all live on Creators/Artist Budgets — but the recoupment handlers never join it, and worse, cadence's own `bookDebitAsEntry` creates `entry_source='bank_statement'` rows as `status='approved'`+`Paid` with `recoupable` defaulting TRUE (`bank-statements.js:170-176`, `index.js:487`) and **no `recoup_reviewed` gate exists anywhere** — so every imported bank debit that names a rostered artist silently inflates that artist's recoupable spend. That is byte-for-byte the "1,972 rows / $3,101,837 claiming to be recoupable against nobody" failure OLD's gate was built to close. Second, the **workflow layer**: recoupment labels (upload batches) don't exist in the schema, the detail view lost its URL-backed statement tabs / four state sections / ~15 per-item controls / bulk bar, and `ufr-bulk` re-stamps already-claimed rows to NOW() — violating OLD's documented PRESERVE rule and silently moving items between partner statements. Totals: **36 defects (7 P1 · 13 P2 · 11 P3 · 5 P4), 7 intentional divergences.**

## 4. Interaction & behavior parity

- **20th-cutoff statement rule — PARITY.** OLD client `statementMonthFor` (`Recoupments.jsx:31-46`): UTC getters, `getUTCDate() >= 21` rolls to next month, Dec 21 → next Jan; day ≤20 stays. NEW server `statementMonthFor` (`statementMonth.js:5-12`): UTC getters, `d.getUTCDate() >= 21` rolls, month>11 → y+1. **The cutoff boundary is identical on both sides** (≤20 stays / ≥21 rolls, UTC), and NEW centralizing it server-side is an improvement (INT-7). Two residues: (a) NEW's `value ? new Date(value) : new Date()` defaults a NULL `ufr_marked_at` to *now*, so a UFR row missing its stamp buckets into the **current** month on `/statements` (`financials.js:253`) instead of surfacing as unstamped — OLD skips no-timestamp rows from month tabs (`:1596-1605`) and the client's `'Unstamped'` group key (`NEW :45`) can consequently never trigger — DEF-RECOUP-33; (b) `statementWindowLabel` tooltips explaining the window are gone — DEF-RECOUP-09.

## 6. Intentional divergences (not defects)

1. **INT-1 Tenancy**: `label_id` on every query, `withTenant` + router-wide `requireApprover` (`financials.js:16`); `artist_meta`/`song_campaign_status` gained `label_id` + per-label unique indexes (`index.js:669-698`).
2. **INT-2 Income axis**: `artist_income` rollup → spend/income/balance/recouped per artist — the spec'd Cadence model (CLAUDE.md M3 "Recoupments v2"); OLD had no income concept on this page (deal-advance comparison instead — its absence still counted, DEF-RECOUP-31).
3. **INT-3 Prior-year generalization**: `prior_year_tag` text (any year) + server-side exclusion from live rollups, replacing OLD's hardcoded `is_2025_expense` (UX regressions counted separately, DEF-RECOUP-34).
4. **INT-4 Brand/kit**: RC-2/RC-5/RC-6; `btn-primary`/`input` kit instead of OLD's raw boom-tinted controls.
5. **INT-5 `ufr` BOOLEAN** instead of OLD's `'Yes'/'No'` TEXT.
6. **INT-6 Purpose-built USD-converted endpoints** (locked-rate `rowUsd`) instead of one raw feed + client FX — legitimate architecture change; the *native-currency display* it dropped is counted (DEF-RECOUP-06).
7. **INT-7 Shared server-side `statementMonthFor`** (`lib/statementMonth.js`) — one rule for stamping and bucketing, an improvement over OLD's client-only helper.
