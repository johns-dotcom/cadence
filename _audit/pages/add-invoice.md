## 2. Summary

NEW is a compact rewrite (~1/6 the client code) that keeps the skeleton — upload → explicit Parse → fields → splits/socials → save, approvers file approved / members file pending — and sheds nearly everything OLD layered on top of it. The single worst gap is the **approval checklist**: OLD forces every admin save through the same ReviewDeck the Approvals queue uses (4 confirmations + 4 written answers, validated server-side BEFORE the insert, stamped onto the row and its split children); NEW has **zero occurrences of "checklist" in the entire repo's ledger path** — an approver's save files straight to `status='approved'` with `recoupable` defaulting TRUE and `artist_campaign`/`is_bulk_deal`/`cobrand` never asked, which is byte-for-byte the "894 invoices / $3.09M approved with nobody looking" failure OLD's gate was built to close. Also missing: the whole document-trust pipeline (validate-invoice, extract-invoice-number mismatch, validate-w9, parse-proof, parse-lines line-item editor), the vendor intelligence (suggest-vendor autofill, W9-on-file banner), the server 409 duplicate gate with `force_duplicate` bypass, vendor-email requirement, the non-admin song+socials gate, urgency-at-create, and `social_handles` persistence (NEW's own Flags page will flag the rows this page creates). Totals: **36 defects (2 P0 · 16 P1 · 11 P2 · 7 P3), 9 intentional divergences.**

## 4. Interaction & behavior parity

- **Parse flow** — OLD `handleParse` (:250-389) fires FOUR parallel calls on one cached document: `/bk/parse` (fields) + `/bk/parse-lines` (`lines`/`lineMeta` editable line-item table) + `/bk/validate-invoice` (`{valid,issues}` red/green banner) + `/bk/extract-invoice-number` (`docInvoiceNumber` → normalized mismatch warning vs the typed number, :845-861). It then runs a **synchronous dup sweep** with the freshly parsed payee+number (:318-343) and routes the toast on `ai_status` (`disabled`/`error`/0-fields-filled/dup-found/similar-found/N-fields, :345-375). NEW `scanInvoice` (:62-91) makes ONE call to `/ledger/parse-invoice`, fills blanks, toasts success or the server error. Validation, number extraction, line items, post-parse dup sweep, and the 0-fields diagnosis are all gone (DEF-ADDINV-08/09/10/13/18).
- **Fill precedence inverted** — OLD parsed-value-wins (`data.invoice_date || prev.invoice_date`, :299-313); NEW typed-wins (`prev.payee || d.vendor_name`, :73-83) with a `currencyTouched` opt-out (:34,77). Re-parsing in NEW can never refresh an already-filled field. DEF-ADDINV-14.
- **Parsed field set** — OLD extracts `artist`, `song`, `vendor_email` too, hands Claude the live artist roster + weighted category vocabulary, post-validates the handle-vs-artist swap (auto-swap + `ai_warnings` + `suggest_socials`) (`bookkeeping.js:4269-4453`). NEW `INVOICE_SCHEMA` has no artist/song/vendor_email and a generic instruction (`claude.js:170-203`). DEF-ADDINV-13.
- **W9 attach** — OLD auto-runs `/bk/validate-w9` on attach (`:393-407`) → spinner, red issue list w/ form_type, or emerald "looks complete · W-9 · signed · dated" (:1057-1093). NEW stores the file silently (DEF-ADDINV-11). OLD also shows "W9 already on file — Preview" under Payee on exact vendor match via `/bk/vendor-w9-status` (:176-186, :1131-1150) and flips the W9 tile to "Already on file / Only upload if updated" (:975-979); nothing equivalent in NEW (DEF-ADDINV-17).
- **Proof attach** — OLD `handleProofUpload` (:391-431): sets `payment_status='Paid'` immediately, then `/bk/parse-proof` fills `payment_date` (toast), `payment_method` **inside the state updater** (`prev.payment_method ? prev : …` so a mid-scan user pick survives), and `payment_ref` ← `reference_number`; Remove resets Unpaid+date (:1010). NEW: `setFiles` only; server marks Paid at create for approvers (`ledger.js:186-191`); the tile's "Auto-marks as paid" hint (:198) is **false for non-approvers** (server forces Unpaid). No date/method/ref extraction. DEF-ADDINV-12.
- **Payee typing** — OLD debounced 400ms `/bk/suggest-vendor`: exact match auto-fills blank `vendor_email/address/bank`, inexact matches render "Did you mean?" chips w/ invoice counts that fill payee+email on click (:152-186, :1113-1129). NEW: nothing (server `/ledger/vendor-suggest` exists :830-853 but this page never calls it). DEF-ADDINV-16.
- **Duplicate check** — OLD: debounced 500ms on payee+invoice_number (:189-199) + post-parse sweep; renders top-of-form banner with entry id/amount/status/date, **status-aware links** ("Open in Approvals →" for pending w/ the ledger-only-shows-approved explanation, else `?focus=<id>`), similar-list, amber Invoice # tint (:753-806, :1213-1253). NEW: `onBlur` only (:52-56, :204,213), one static sentence (:235), no links, no similar tier, and non-approvers get a silent 403→null (`/ledger/check-dup` sits below `requireApprover`, `ledger.js:84`). DEF-ADDINV-18/15.
- **Client validation** — OLD `validationError()` (:444-476): payee+amount+date+**invoice # required**, **vendor email required + regex**, and for non-admins song (splits count) + ≥1 social handle. NEW `create()` (:112-116): payee, amount>0, date, invoice # (non-reimb). Email optional, no non-admin gate. DEF-ADDINV-21/22.
- **THE APPROVAL CHECKLIST (P0)** — OLD `handleSubmit` (:481-488): non-admins submit straight through (their row lands pending and gets its checklist in the Approvals queue); **admin-level saves open the ReviewDeck** (:1786-1893) with `ApprovalChecklistFields` (:1823-1852) — 4 CONFIRMATIONS (artist/song/amount/category, tick-only) + 4 ANSWERS (bulk_deal/cobrand/recoupable/campaign, Yes/No both written) per `lib/approvalChecklist.js:24-40`; `answerCobrand` forces campaign=yes + category=Marketing and re-arms the category tick (:63-69); edits write through to the form (`onFieldChange` :1840-1843); `reviewChecks` cleared on every open so answers are never inherited (:53-57); Save disabled until `checklistComplete` w/ outstanding-items hint (:1874-1889); the payload travels as `checklist: checklistPayload(reviewChecks)` in POST `/bk/entries` (:1874). **The form's own cobrand/bulk boxes deliberately do NOT pre-fill the review's answers** (`reviewChecks` starts `{}`; `context` passes them for display only, :1845-1850). DEF-ADDINV-26.
- **Reset & unsaved-warning** — OLD resets the form in place for rapid multi-entry w/ green success banner (:562-599) and arms `beforeunload` while dirty (`useUnsavedWarning` :124). NEW navigates to `/ledger` (approver) or `/` (:151) and has no beforeunload anywhere (grep). DEF-ADDINV-28/34.

## 6. Intentional divergences (not defects)

1. **INT-1 Tenancy**: `label_id` on every query, `withTenant`, per-label `vendors` upsert, R2 keys `label-{id}/ledger/…` (`ledger.js:63,86-91,216-221`).
2. **INT-2 Open-to-all-members create + pending routing** with role-dependent subtitle and "Submitted for approval" toast (`App.jsx:180`, `AddLedgerEntry.jsx:149,159`; `ledger.js:78-84,183`) — documented Cadence design (CLAUDE.md M2).
3. **INT-3 Atomic multipart create** — files ride the INSERT request instead of OLD's post-create uploads whose failures were swallowed (`.catch(() => {})`, OLD :578-596).
4. **INT-4 Approver-gated "Mark as already paid"** (client :219-230; server :183-191) — OLD let any bk-granted user create Paid rows; NEW is auth hardening.
5. **INT-5 Brand accent + ui kit** (`.input/.label/.btn-*`) per RC-2/RC-5/RC-6.
6. **INT-6 Currency list** 4 → 12 (`cadence constants.js:13` vs OLD's inline USD/EUR/GBP/CAD :1266-1277). PAYMENT_METHODS identical (both `['ACH','Check','Wire','Credit Card','PayPal','Cash']`).
7. **INT-7 Toast system** replaces inline alert banners (NEW-wide pattern).
8. **INT-8 Socials-with-amounts materialize as real Marketing child rows** (`ledger.js:335-352,397-407`) — NEW's documented allocation model (commit 82fa2b0); the metadata it drops is counted separately (DEF-ADDINV-26).
9. **INT-9 Parse spend framing** — explicit Parse button to conserve monthly AI quota (comment :16-22) matches OLD's explicit-button behavior; the panel copy is NEW-only.
