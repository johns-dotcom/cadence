OLD: `/flags` — `boom-dashboard/client/src/pages/Duplicates.jsx` (3,043 lines; filename is legacy — App.jsx:196 routes `/flags` to it, `/duplicates` redirects at :197) + `server/routes/flags.js` (1,581 lines) + three statements-engine feeds (`/statements/flags`, `/statements/unmatched`, `/statements/duplicate-pairs`, statements.js:3292/4648/9771).

## 1. Layout & structure

**OLD** is a two-pane hub. `PageHeader` "Flags" with a two-figure subtitle ("N need a decision · M fields incomplete", D:830-845) and a refresh icon-button (D:846-855). Below `lg`: a full-width `<select>` with `<optgroup>` per domain group (D:862-877). From `lg`: a sticky 224px left rail (`FlagsNav`, D:1181-1223) grouped in fixed order **Money → Ledger → Catalog → Artists** (`GROUP_ORDER`, D:55-56), each category row showing a severity dot, short label (`SHORT_LABEL`, D:101-127), and tabular count; problems sort above completeness inside each group, then by size (D:643-648); empty categories render disabled (D:1200-1216). Right pane: show-low + show-dismissed toggle row (D:894-909), an **Overview** default view (problem cards grid + "Incomplete fields" progress-bar strip, D:1232-1332), or a section view with header (severity dot + label + count + "← All flags" + description, D:928-945), a `ListSearch` filter (D:957-968), and a per-kind section body dispatched by `CategoryBody` (D:1335-1445). Active section persists in the URL as `?tab=` (D:250-256). Overlays: single/multi `FilePreview` (D:1027-1040), split modal (D:1045-1135), and the `ReviewDeck` for duplicate payments (D:1552-1664).

The page classifies **26 flag kinds**: 25 mapped in `CATEGORY_CLASS` (D:62-91 — 8 Money, 9 Ledger, 5 Catalog, 3 Artists) plus `artist_placeholder`, which arrives from the server (OF:1376-1382) and renders through the unknown-kind fallback (`classify()` defaults to Ledger/problem, D:93-97) — a deliberate rule so a new server-side check can never silently vanish.

**NEW** is a single-column page: `PageHeader` "Data Quality", a flat 7-tab pill strip (Releases / Artists / Vendors / Invoices / Ledger flags / Normalization / Dismissed with counts, DQ:46-61), then one `Section` per tab of `GroupCard`s (DQ:63-148). No rail, no grouping, no overview, no URL persistence, no search, no overlays. Everything mounts under `AdminRoute` (cadence App.jsx:170) and the nav item is admin-only (cadence Layout.jsx:302); the server router is `requireAdmin` throughout (NF:10). OLD's page was `canView`-gated per user (boom App.jsx:196 has no admin guard; Layout.jsx:568) with only the money sections role-gated server-side (OF:1423-1425: ledger flags need Approver+, bank txn flags need Admin+).

## 3. Copy & content differences

- OLD per-category `label` + long `description` (server-authored, OF:1244-1406) render in the section header; e.g. duplicate invoices explain the alias/split-slice rules (OF:1280). NEW has only tab labels and empty-state one-liners — no category descriptions anywhere.
- OLD subtitle math: `problemCount` / `incompleteCount` derived from classification so they always sum to the API total (D:626-639). NEW subtitle: "Find and fix duplicates, mismatches, and messy attribution" (DQ:53), static.
- Merge confirms: OLD names the survivors and the folded rows explicitly — release: "Merge N releases into X… permanently deleted" (D:717), artist: "…releases, contracts, and expenses will be reassigned" (D:735), vendor: bulleted source list + alias note + "Left alone:" list (D:793-797). NEW: one generic `Merge ${label}? This rewrites references and cannot be undone.` for all kinds (DQ:30).
- OLD flag row copy is didactic ("(no song)", "(empty)", `→ suggested: "X"`, `→ song "Y" is by Z`, D:2860-2930). NEW: `payee · artist · song — detail` one-liner (DQ:112) with server detail strings like `Roster spells it "X"` (NF:165) — the suggestion text survives in `detail` but is not actionable.
- OLD dismissed rows: human sentence with who/when (D:3018-3027). NEW dismissed rows print the raw `flag_key` in mono (`reldupe:12-15`) + kind + name (DQ:143) — machine key as primary copy.
