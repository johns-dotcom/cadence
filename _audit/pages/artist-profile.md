## 1. Layout & structure

**OLD** (ArtistProfile.jsx:525-1059): Breadcrumb (Artists › name, :527-530) → header (80px avatar w/ `not_found` fallback, `text-3xl font-black` name, genre + release count + active-contract pill, **plus a row of artist_links chips** :552-562) → 2 stat cards Releases/Upcoming (:566-576) → budget progress card w/ 3-band green/amber/red bar (:578-592) → 8-tab strip (Overview / Spotify(icon) / Releases(n) / Spends(n) / Links(n) / Development(n) / Contracts(n, permission-gated) / Documents(n live via onCountChange)) (:507-523,594-608) → tab bodies. Loading = `Skeleton.ArtistProfile` (:455-457); not-found = message + "Back to roster" link (:459-466).

**NEW** (ArtistProfile.jsx:175-379): hand-rolled breadcrumb ("Roster › name", :178) → header (64px avatar, `text-2xl font-bold` name, genre + release count + active-contract pill + archived pill, **no links row**; NEW-only action buttons: Spotify sync / Edit / Archive-toggle / Delete :194-199) → 2 stat cards (:203-206) → budget card w/ 1-color bar + rose-on-overrun (:209-219) → same 8 tab KEYS (:137-146,222-226) but four of the eight bodies are drastically thinner (see §4) → NEW-only edit-artist modal (:353-378). Loading = plain "Loading…" text (:124); not-found = plain text (:125).

Structural deltas: header links row removed; header gains a 4-button action cluster (edit/sync/archive/delete — none exist on OLD's profile page); Contracts tab no longer conditionally rendered; the Spotify, Links, Spends and Documents tab bodies are rebuilt as much smaller surfaces (§4); Overview loses its third card (Deal History).

## 4. Feature & interaction differences

### Features in OLD missing/changed in NEW
- **Spotify tab gutted**: OLD is a live Spotify surface — loading spinner, error state naming the env vars, "not found on Spotify" null state (:94-123); stat cards PopularityRing (SVG ring, color-banded ≥70 green/≥40 amber/else red, :60-76,134-139), Followers, Tracks Found, Releases, Markets (:140-163); genre chips (:167-174); "Open on Spotify" link (:177-183); Top Tracks list w/ rank, album art, per-track popularity bars (:186-216); discography grid (18 covers, album/single split subtitle, :220-242). Backed by `GET /:id/spotify` (OLD server :1123-1222: token, id resolution, profile+albums+track-search fan-out, 3-page album pagination). NEW tab = three static cards (Monthly listeners / Followers / Popularity) read from stored artist columns (:243-256); the live endpoint does not exist in NEW. NEW's partial analog is `POST /:id/sync-spotify` (NEW server :15-37) which stamps followers/popularity/image/genre onto the row.
- **Links tab reduced to read-only social chips**: OLD manages `artist_links` rows (platform select from 14 PLATFORMS, url, optional label; add form :727-759; delete on hover :780-785; `POST/PUT/DELETE /:id/links` OLD server :534-582) **plus** a "Release Links" card aggregating 5 URL fields (`spotify_uri, apple_music_link, presave_link, presave_analytics, ugc_link`) across every release with a link back to the release (:687-815). NEW renders chips for 7 artist-row social columns (SOCIALS :25-33, :272-280) — no CRUD (edit only via the artist Edit modal), no labels, no release-link aggregation; the links endpoints are absent from NEW's server entirely.
- **Spends tab reduced to the category bars**: OLD shows a 3-card summary strip (Total spend w/ per-currency totals, Unpaid in red, Top category, :902-919) + a full approved-expense table (Date/Payee/Song/Category/Amount/Status columns; Paid/Unpaid/Partial pills; Recoup + Cobrand badges; per-row "Ledger →" deep-link to `/bk/ledger?focus=<id>` gated by `canView('/bk/ledger')`, :921-975). NEW's Spends tab re-renders the same SpendingByCategory bars as Overview plus a single total (:264-269); the aggregate no longer returns expense rows at all (NEW server :80-109).
- **Contracts tab permission gate dropped (both layers)**: OLD hides the tab unless `canView('/contracts')` (:518, body re-checks :997) AND the server returns `[]` for roles below approver (OLD server :436-451). NEW always shows the tab (:144) and the server returns contracts to every label user (:87-92). NEW also drops the per-contract embedded `FilesPanel entityType="contract"` (view/download the actual document, :1026-1032) and the `notes` line (:1021); adds a "Manage →" link to /contracts (:314).
- **Per-row release archive** gone: OLD每 release row has an archive/unarchive button (`PUT /releases/:id/archive`, optimistic update, amber toggle, busy state, :393-406,:854-869) + archived badge + `opacity-60`. NEW release rows have none (:148-159).
- **Checklist completion %** gone: OLD computes 14-key completion (:31,:49-52) and renders bars in Overview upcoming rows (:624-635) and Releases rows (:848-852). NEW can't — its aggregate selects only 6 release columns (NEW server :82-85), no checklist fields.
- **Overview Deal History card** gone: OLD lists 5 most recent deals (stage, rep, date, :664-680) from the aggregate's `deals` (matched by `LOWER(artist_name)`, OLD server :453-455). NEW neither queries nor renders deals.
- **Devlog date input** gone: OLD's add form has a date field defaulting to today (:302-307); NEW has only type + note (:285-291) — `log_date` is server-defaulted (`CURRENT_DATE`, NEW server :194) and not user-settable.
- **Devlog delete rule** gone: OLD hides the trash unless `isAdmin || entry.created_by === user.id` (:294,:358) and the server 403s otherwise (OLD server :1327-1350). NEW shows delete to everyone (:298) and the server deletes unconditionally (NEW server :205-217). NEW also drops the confirm dialog.
- **Documents FilesPanel** replaced: OLD embeds the shared FilesPanel (drag-highlighted dropzone, upload spinner + error banner, per-file size/date/uploader, confirm-on-delete, `onCountChange` feeding the live "Documents (N)" tab label, :1042-1058 + FilesPanel.jsx). NEW has a paperclip label w/ `dropTarget` drag-drop + chip list (no metadata, no confirm, no count in the tab label, :333-350).
- **Tab counts**: OLD Spends(n), Documents(n live); Links(n) counts artist_links + release links across the 5 URL fields (:503-505,:507-523). NEW drops the Spends and Documents counts and Links(n) counts only non-empty social columns (:137-146).
- **Skeleton + not-found affordance**: `Skeleton.ArtistProfile` and the "Back to roster" link both gone (§2).

### Features in NEW not in OLD (on this page)
- **Edit-artist modal** (:353-378): 13 fields (EDIT_FIELDS :35-44, incl. manual Spotify stat entry) + bio, via `PATCH /:id` (NEW server :138-158, PROFILE_FIELDS allow-list :42-47). OLD's profile page has no edit surface at all. Hand-rolled `fixed inset-0` overlay — not `ui/Modal`, so no focus trap / escape stack; closes only via backdrop/X/Cancel.
- **Spotify sync button** → `POST /:id/sync-spotify` (:88-93; NEW server :15-37). Rough analog of OLD's bulk `POST /artists/sync-images` (OLD server :977+), but per-artist and stat-stamping.
- **Archive toggle in the header** (:83-86,:197) via `PATCH /:id {archived}`. OLD archives from the roster page via `PATCH /:id/archive`, which also stamps `archived_at`/`archived_by` (OLD server :897-926) — NEW's generic PATCH stamps neither.
- **Delete-artist button** (:118-122,:198) — see AP-6; OLD exposes delete only on the roster with heavy guards.
- **Archived pill** in the header (:191); upcoming filter excludes `status === 'Archived'` (:130).
- **Toasts** for every mutation (ToastContext) where OLD mostly `console.error`/`alert`s.

### Interaction/UX differences
- Devlog add: OLD is a `<form onSubmit>` (Enter submits, native `required`, inline error text :300-329); NEW is button-click only w/ toast validation (:106-113).
- Devlog list update: OLD prepends the POST response (server re-fetches enriched row so shape matches list, OLD server :1303-1312); NEW re-fetches the list (:111).
- OLD devlog fetch failure is tolerated (`.catch(() => setDevlog([]))`, :420-426) and the page still renders; NEW's `Promise.all` couples artist + log — either failing toasts "Failed to load artist" and, if the artist call also failed, dead-ends (:64-71).
- Link opening: both `target="_blank"`; NEW file-open goes through a signed-URL fetch then `window.open` (:81) vs OLD direct `getFileUrl(filename)` href (FilesPanel.jsx:136-140) — see intentional divergences.
