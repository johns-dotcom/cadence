## 1. Layout & structure

- **OLD**: full-height column — sticky toolbar (search / amount / sort select row, then a quiet 9-filter strip; right side: "N of M" count, other-half link, Undo, Clear, admin Export menu, Columns panel) → `DuplicateInvoicesFlag` amber banner → error / focus-missing banners → sticky bulk bar (only with a selection) → horizontally-scrolling table with a **single frozen `<td>`** per row containing checkbox + flag + Date + Payee + Artist + Amount (+ Currency when visible) as internal flex cells (`FW` widths :2756, comment forbidding splitting the cell :2747-2755) → grow-sentinel row → TOTAL `<tfoot>` with the frozen cell spanning `FW.pick+flag+date+payee+artist` widths and the amount block spanning `FW.amount+currency` (:4913-4931). Mobile `<768px` is a separate render branch (:2821-3074): header + sticky search/Filters/Undo row, `LedgerCard` list with 100-row "Load more", `FilterSheet`, `LedgerEntrySheet`.
- **NEW**: `PageHeader` (title + 8 action buttons) → one wrap-row filter bar (search, amount, category, payment, method, source, ⚠ Flagged, More filters, Columns) → optional advanced-filter row → status chips (all/approved/rejected) + "N of M" → card-wrapped table with **one sticky first column** (whichever column is first in the visible set, `Ledger.jsx:482,493`) → `<tfoot>` totals line spanning all columns (:536-540) → fixed bottom-left undo bar. Mobile `<768px` swaps the table for a card list + sticky totals card (:430-469); the desktop filter bar and header buttons render unadapted.
- Structural deltas: NEW freezes only ONE column (OLD freezes six fields in one cell); NEW has no bulk bar, no banners row, no sticky toolbar (page scrolls the whole card), no incremental render sentinel; split children live in a lazy-fetched expansion (`?parent=`) instead of arriving in the main payload.

### Behaves differently

- **Amount query grammar** — OLD `parseAmountQuery` (utils.js:247-280): strips `$ , spaces`; bare `500` = **exact match ±$0.005**; `>500` strict; `<500` strict; `>=`/`<=` supported; invalid input → null → no filter + amber border + tooltip. NEW `amountPred` (:27-35): bare `500` = **`v >= 500`**, `>500` treated as `>=` (regex `^>=?` collapses both), `<500` treated as `<=`, no `$`/comma stripping, no invalid-input signal. Typing "500" in NEW returns every row ≥ $500 where OLD returned the $500 rows. LED-5.
- **Inline-edit vocabulary** — OLD live controls on ~20 fields: date (`<input type=date>`), payee, artist, amount (click-to-edit span), currency select, description, category select, song (per-artist datalist), inv #, email, address, bank, **socials popover** (platform/handle/$amount rows + per-artist tag on split families, saved via `social_handles`), rep select, method select, **terms select that writes `scheduled_payment_date`** via `calcDueDate` (Net 15/30, Hold clears) (:4278-4302), **due-date input that back-writes `payment_terms='Custom'`** (:4304-4327), paid-by, date-paid, pay-ref, notes; YN badge toggles: Reimb?, QB?, Recoupable?, UFR? (N/A chip when not recoupable :4508-4520), Campaign? (3-state Yes/No/unset cycle :4529-4547), Cobrand? (forces category Marketing locally, mirroring the server rule :4562-4578), Bulk Deal?. NEW inline: 14 click-to-edit cells (artist/song/description/category/inv#/amount/method/rep/email/address/bank/terms/notes/ref) + toggles recoupable/cobrand/bulk + paid pill; payee, date, currency, paid-by, date-paid, scheduled, socials, UFR, Campaign, Reimb, QB are **not** inline (modal-only or read-only; QB doesn't exist). Terms edits do not derive a due date (NEW's Due column is display-only derivation :54-62). LED-8/LED-6.
- **Socials** — OLD: editable `social_handles` array, children inherit read-only from the parent filtered by `filterSocialsForArtist` (:4204-4241). NEW: read-only column derived from `artist_breakdown` handles or a "Socials:" note regex (:37-53); `expenses.social_handles` (which NEW's Artist Campaigns writes) is never read here — and after a NEW split, `artist_breakdown` becomes the `{origin, splits}` snapshot, which `socialsOf` can't parse. Part of LED-8.
- **Comma auto-split** — OLD: server-side in PUT, comma **or slash**, guarded by `no_auto_split` (set by unsplit precisely so fixed comma-in-title songs stay fixed), even division w/ remainder-to-first, children inherit approved/paid stamps (bookkeeping.js:1755-1841). LED-16.
- **Re-split** — OLD replaces existing children in one transaction (refusing only when a receipt child exists). NEW 409s "already split — unsplit it first" (:1104-1105). LED-17.
- **Unsplit** — OLD: admin-gated, `window.prompt` pre-filled with the deduped comma-joined child songs (editable), restores amount by summing, sets `no_auto_split`, artist left as-is. NEW: Approver+, `window.confirm`, exact snapshot restore incl. artist/song, refuses on child files/installments, no song prompt. Net: NEW restore fidelity better, protection rules different (fold w/ LED-16/17).
- **Paid cycle** — same Unpaid→Paid→Partial→Unpaid order; OLD = one `PUT` carrying status+paid_by+date (documented race fix) + undo + dup warning; NEW = `POST mark-paid` for the Paid step (server stamps, family cascade, FX, vendor notify) and `PATCH` otherwise (also family-cascaded, :279-298). NEW's mark-paid requires `status='approved'`, so cycling the pill on a **rejected** row (visible under NEW's rejected chip) 404s "Entry not found or not approved" (:489-495). LED-29.
- **Undo** — both 20-deep + `z`. OLD: per-edit toast Undo (5s, `revertEdit` closure targeting the exact record — the stale-closure fix is documented :1742-1763), bulk undo via `previous[]` regroup, timer-clear so back-to-back saves don't truncate the window (:1733-1740). NEW: persistent bottom-left bar + `z`; covers `commitEdit` writes only (cyclePaid, drawer actions, splits not recorded); `undoLast` fires its PATCH inside the `setUndoStack` updater (side effects in a state updater — double-fire under StrictMode) (:137-145). LED-19.
- **Totals** — OLD sums `filtered` rows (children included when their rows match; voided rows INCLUDED), currencies ordered by magnitude, USD-equivalent line via `usdItemsSuffix` (:2396-2403,4909-4931). NEW sums `family_amount` over parents, **excludes voided** (:347-353), insertion-order currencies, no USD line. NEW's voided exclusion is arguably more correct; the missing USD line is LED-22.
- **Sorting** — OLD: 8 named sorts (date/due/paid/uploaded × dir) with empties-pushed-to-end + id tiebreaker (:2146-2154). NEW: any-column click sort, no empties rule (empty strings sort first ascending), amount numeric, others localeCompare (:337-343).
- **Column persistence** — OLD stores hidden-list under one global key (`bk_ledger_hidden_cols`); NEW stores the visible-list per `label:user` and validates keys against `ALL_KEYS` (:199-205). Intentional improvement (multi-tenant).
- **Void** — OLD: admin-only, cascades to children, keeps payment_status, detailed confirm copy (:1988-2010; server :2173-2217). NEW: Approver+, **no child cascade**, resets `payment_status='Unpaid'` (paid state lost on unvoid), bare confirm in the drawer (ledger.js:1666-1695; LedgerEntryDrawer.jsx:94-98). LED-27.
- **Delete** — OLD: modal confirm, soft delete + children, bank-row unlink (bank-half), no restore UI on ledger (restore lives elsewhere). NEW: `window.confirm`, family-wide soft delete via `COALESCE(parent_id,id)` (:2057-2072) — cascade parity good; restore route exists (:1044) but no ledger UI. LED-26 (cosmetic).
