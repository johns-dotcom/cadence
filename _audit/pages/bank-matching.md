## 2. Summary

NEW rebuilds the page's SKELETON faithfully — queue + chips, completion card with the explained-vs-invoice-backed distinction, likely-accept, review deck, unmatched-ledger panel with the three-band partition and no-dismiss rule, rematch/funding/duplicate/auto-decision panels, months strip, rules — and the server keeps most of OLD's hard-won invariants (rejection memory on unmatch, capacity model, prepayment guard, booked-vs-matched separation, equality-never-substring rules, unrematch restore, one-proposal-per-orphan). But the page is ~11% of OLD's line count and the missing 89% is mostly WORK CAPABILITY, not chrome: no dimension lens or artist attribution anywhere in the queue, no way to BOOK an open row from the table, no batch (vendor-clustered) view, a deck reduced from an 8-action/9-card-type instrument with full undo to a 3-action/2-card-type swiper with none, and five server endpoints (attach, unattach, split-book, unrematch, funding-pair undo) that exist with **no client caller at all**. Two OLD-documented regressions were re-introduced: the completion card ignores the statement selector (mixed denominators), and per-statement "left" counts exclude the needs-invoice pile (the 146× selector drift OLD's comments memorialize). One data-integrity regression: NEW's dismiss silently unlinks a matched/booked row, orphaning the created ledger entry.

- [INT] `label_id` scoping on every query + `requireAdmin` router gate (≈ OLD's per-handler isStrictAdmin); logActivity in place of bk_audit_log.

- [INT] Duplicate-merge carries R2-key doc columns only (no legacy `*_data` blob plumbing) — cadence is R2-native; and it repoints `bank_txn_invoice_links` (closing an OLD gap).
- [INT] book-income validates the income type against the live per-label vocabulary and claims the txn atomically (409 on race) — parity-plus.
- [INT] Deck pointer-capture bail-out and 409 claimed-set self-heal are deliberate fixes of two OLD deck bugs (SRD:11-19).
- [INT] Months strip lives on this page with reconcile gated on zero open debits + activity-bot events — placement/behavior choice, arguably better than OLD's library placement.
