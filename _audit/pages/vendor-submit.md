# Vendor Submit (public form)

## 1. Purpose & pairing
Public, unauthenticated vendor invoice/reimbursement intake that creates a pending `expenses` row.
- OLD: `boom-dashboard/client/src/pages/VendorSubmit.jsx` (1,829 lines) + `boom-dashboard/server/routes/vendor-submit.js` (1,463 lines), route `/submit` (`boom App.jsx:171`).
- NEW: `cadence/client/src/pages/VendorSubmit.jsx` (372 lines) + `cadence/server/routes/vendor.js` (332 lines), route `/submit/:slug` (`cadence client/src/App.jsx:113` — the param actually carries the unguessable `vendor_form_token`, see `cadence server/routes/vendor.js:39-46`).
- NEW is roughly a 1:5 condensation. The wizard skeleton, uploads, AI autofill, dup check, drafts and extra emails survived; the entire payment-details subsystem, roster picker, AI pre-submit validation, and most vendor-facing guidance did not.

## 5. Behavior / interactions diff
- **Draft autosave**: OLD saves only when meaningful content exists (`boom :490-492`), pauses autosave while the resume banner is showing so the stored draft can't be clobbered (`boom :497`), stamps `savedAt`, and resume drops back to the Documents step with "your files will need re-attaching" (`:510-531,1090-1107`). NEW autosaves unconditionally as soon as ctx loads (`cadence :65-68`) — **the blank form overwrites the saved draft on page load, before the user can click Resume**, so `resumeDraft` (`:70-78`) restores an empty draft; and because even an untouched visit writes a draft, the "You have a saved draft" banner shows for every returning visitor. **P1 defect.**
- **W9 check**: OLD debounced-as-you-type (500 ms, min 3 chars) with 429-tolerant state keeping (`boom :561-593`); NEW fires only on name-field blur (`cadence :247,81-85`) — P3.
- **Dup check**: OLD debounced live while typing invoice# on step 2 with inline amber panel (`boom :615-641,1624-1639`); NEW runs once, at step 2→3 transition, result shown on step 3 (`cadence :132-139,164`) — P3 (later + easy to miss).
- **AI autofill**: OLD parses once at the step-2→3 click, gates progression on number match, snaps parsed artist to roster casing, surfaces prefill summary/warnings/suggested socials (`boom :738-865`). NEW parses immediately on file choose (`cadence :107-130`), again via `/check-invoice-number` at step 2→3 (`:160-162`), and the server parses a third time at submit (`cadence vendor.js:224-230`) — 3 paid AI calls per submission vs OLD's 2; silent prefill (no verify banner). P2 (cost + lost verify affordance). NEW also has a dead duplicate of the autofill fn (`autofill`:87 vs `autofillFrom`:112 — only prefill-precedence of `amount` differs; code smell, P3).
- **Validation model**: OLD blocks per step with specific copy (`boom :718-736,743-747`) and disables Submit until the named-missing list is empty (`:1814-1820`); NEW step gates are near-copies of OLD's copy (`cadence :142-165`) but submit-time requirements diverge: song per row NOT required (OLD `boom :877-878` + server `:816` area), rep NOT required (OLD server `boom vendor-submit.js:852` area — `'Please select your Boom Rep.'`), socials NOT required (OLD `boom :904-907`, server `:869-871` area). NEW adds a requirement OLD lacks: splits must sum exactly to the invoice total (`cadence :180-181`).
- **Reimbursement W9 skip**: parity — both skip W9 in reimb mode and require receipt (`boom :694,744-746`; `cadence :156-157,195`).
- **Sandbox / admin preview**: OLD offers `?sandbox=1` dry-run (admin-authed, returns `would_create` without writing, `boom vendor-submit.js:1131-1168`) and `?admin_preview=1` skip-validation banner (`boom VendorSubmit.jsx:1009-1048`); NEW has neither — P3.
