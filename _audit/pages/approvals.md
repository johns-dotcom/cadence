## 2. Summary

NEW keeps the card-queue silhouette (search/rep/category/sort toolbar, j/k/a/r/⇧A hotkeys, scan banners with Re-scan, edit-in-place that re-triggers scans, vendor-allocation auto-split on approve, alias add, per-entry `bk_audit_log` trail, rush toggle, name-mismatch flag, notify toggle + EmailPreviewModal, Cobrand / Bulk-deal `?`-chips) but **the control layer that made OLD's Approvals an audited attestation is gone end-to-end**: the 8-question approval checklist (4 confirmations + 4 written answers) has no client deck, no server gate, and no stored record — NEW's approve is a one-UPDATE status flip, and `recoupable` / `artist_campaign` / cobrand⇒Marketing are never decided or written at approval. The second review (per-document W9 deck with prefill-accepted accounting) is absent. So are all four queue-time risk annotations (possible-duplicates, unknown-artist/song suggestions, payment-details fraud check, alias/amount discrepancy silencers), per-discrepancy dismiss, the socials editor, the split-before-approve editor, the Recent Activity panel, and the archive link. **Totals: 45 defects (1 P0 · 13 P1 · 13 P2 · 18 P3), 10 intentional/additive divergences.**

## 4. Interaction & behavior parity

### 4.1 The checklist deck (OLD's core; absent in NEW)

Every OLD approve entry point — row button (labeled **"Review"**), `a`, ⇧A, "Review all N", bulk-bar "Review N" — opens `ApprovalChecklistDeck`, never approves directly (`handleApprove`/`handleBulkApprove`, BkApprovals.jsx:527-543; comment: "a bypass anywhere makes the checklist optional in practice"). The deck (ApprovalChecklistDeck.jsx):

- **4 confirmations** (artist / song / amount / category — `CONFIRMATIONS`, approvalChecklist.js:24-29): tick buttons beside **editable fields showing the PENDING value** (`pending` memo, Deck:73-83). Editing a field PUTs on blur, updates drafts, and **clears that confirmation** (`saveField`, Deck:96-108); amount edit is guarded `> 0` (Deck:100). Fields are uncontrolled inputs re-keyed on value (Fields:96-113).
- **Category** is a grouped `<optgroup>` select from `useCategoryGroups('expense')` with flat-list fallback, an **off-list stored value injected as an option** so the select never silently blanks, and **disabled while cobrand=yes** (Fields:60-91).
- **4 written answers** (bulk_deal / cobrand / recoupable / campaign — `ANSWERS`, approvalChecklist.js:34-39) as Yes/No button pairs, **nothing pre-selected** ("this checklist records that a PERSON decided", Fields:150-163).
- **Cobrand implication** (`answerCobrand`, approvalChecklist.js:62-69): yes ⇒ campaign forced true + campaign buttons disabled (Fields:139-146) + category re-armed (tick cleared) in exactly the two directions the category moves; blue notice "the category will be saved as **Marketing**. Confirm the category again." (Fields:200-204).
- **Stored-value CONTEXT lines**, never pre-answers: "Marked bulk on the form — 12 videos. Your answer is what gets recorded." (Fields:164-172), "Ticked cobrand on the form…" (:173-177), amber "Currently marked NOT recoupable. Someone set that deliberately — the column defaults to yes." (:181-186).
- Approve disabled until `checklistComplete` (approvalChecklist.js:72-79); outstanding-items hint line (Deck:367-373); **Skip** leaves the row pending (Deck:228); Rush pill on the deck card (Deck:278-292); inline document preview panel toggle "P preview · Esc close" (Deck:230-252,345-354); per-card **SocialHandlesEditor** (Deck:313-331); staged breakdown travels in the approve payload (Deck:216-218); approved rows are removed from the page and vendor emails **append to a queue drained after the deck closes** (BkApprovals.jsx:547-552, 2126-2151).

NEW has none of this: `approve()` POSTs immediately (Approvals.jsx:45-53), `a` fires it (:135), ⇧A / "Approve All" runs `approveMany` behind a `window.confirm` (:64-75,169). The Cobrand / Bulk-deal `?`-chips (:201-202) are optional pre-toggles on the row, not recorded answers — exactly the "nobody ever looked" state the OLD feature exists to eliminate. → **APR-1..9, APR-15, APR-42.**

### 4.6 Split / breakdown

OLD "Split" opens an **editable** Artist Breakdown panel (artist/song/amount rows, add/remove, seeded from `artist_breakdown` JSONB, :232-262,1811-1837) whose rows travel in the approve payload (Deck:216-218) and drive the server's split-on-approve. NEW "Split" (:263-280) is a **read-only** viewer of the vendor's allocation with a note that splits apply automatically on approve; the reviewer cannot correct or create an allocation. → **APR-11.** (NEW's auto-apply of the vendor's own allocation on approve — `applyBreakdownSplits` — is the documented parity for the happy path.)

### 4.7 Notify vendor + email queue

OLD: NOTIFY VENDOR pill **defaults OFF**, disabled without an email (:2011-2053); reject form pre-checks it only for vendor-submitted-with-email (:586-592); server prepares the full email payload (`prepareEmail(kind,{entryId, cc_rep:true})` → to/cc/subject/html/attachments) and returns `pending_email`; client queues them into `EmailPreviewModal` with subtitle "N more queued · Entry #id" (:2126-2151). NEW: "Notify vendor" **defaults ON** whenever `vendor_email` exists (:42); approve/reject always POST `notify:false` then the client opens `EmailPreviewModal` with a client-built `ctx` (to/vendorName/invoiceNumber/amount/currency/reason — :48,59) and the modal fetches its own preview from `/email/preview`. Functional consequences: no `cc_rep` (rep never CC'd), and any API caller omitting `notify` gets a **silent auto-send with no preview** (ledger.js:432,457 — `req.body.notify !== false`). → **APR-30, APR-31.** Architecture swap itself: intentional (INT-5).

3. **Toasts + Skeleton** — `ToastContext` + `Skeleton.Card` replace OLD's inline toast/error divs and spinner (NEW kit convention).
4. **File access** — signed-URL GET (`/entries/:id/file/:type` → `{url}`) replaces OLD's `?token=` query-param URLs (documented security hardening in CLAUDE.md).
5. **Email plumbing** — client-side `/email/preview` + `/email/send` with `{kind, ctx}` replaces server-returned `pending_email` payloads; same review-before-send capability, queue mode preserved (`items=[…]`, EmailPreviewModal.jsx:13-17). Behavioral deltas filed separately (APR-30/31).
6. **Activity-stream bot** posts on approve/bulk-approve (ledger.js:433-436,1030-1033) — additive.
7. **Rush cascades the split family** (ledger.js:1362-1367) — additive consistency win.
8. **Receipt file chip** on the card (Approvals.jsx:259) — additive (OLD showed invoice/W9 only).
9. **Pending-count nav badge** (`GET /ledger/pending-count`, :149-159) — additive.
