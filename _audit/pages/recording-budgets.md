# Recording Budgets — parity audit

Design-token deltas covered by RC-1..RC-6 in `_audit/01-design-system.md`; not re-reported per element.

## 1. Files compared (purpose & pairing)

| Side | Client | Server |
|---|---|---|
| OLD (truth) | `boom-dashboard/client/src/pages/Budget.jsx` (216 lines — index) + `BudgetDetail.jsx` (1,069 lines — detail w/ ArtistPicker, PlanningTab, SectionCard, LineItemRow, CostsToDateTab) | `boom-dashboard/server/routes/budgets.js` (625 lines): GET `/` (:101), GET `/:id` (:151), POST `/` (:208), PUT `/:id` (:248), DELETE `/:id` (:288), POST `/:id/approve|lock|reopen` (:310/:329/:348), POST/PUT/DELETE `/:id/line-items(/:itemId)` (:370/:403/:448), GET `/:id/actuals` (:485), PUT `/expense/:expenseId/section` (:603). Tables `recording_budgets` + `recording_budget_line_items` (+ `expenses.budget_section_override`) |
| NEW | `cadence/client/src/pages/RecordingBudgets.jsx` (131 lines — single page, inline expander) | `cadence/server/routes/recording-budgets.js` (124 lines): GET `/` (:16), GET `/:id` (:42), POST `/` (:51), PATCH `/:id` (:66), POST `/:id/status` (:83), DELETE `/:id` (:99), POST `/:id/items` (:105), DELETE `/items/:itemId` (:119). Tables `recording_budgets` + `recording_budget_items` (cadence `server/index.js:751-778`) |

OLD models the label's two Excel templates faithfully: a budget is a typed document (**Budget | Fund**) with a rich header (artist FK-or-freeform, project, release, currency, advance, fund amount, tracks, contingency), six qty×price sections, a draft→approved→locked lifecycle, and a Costs-to-Date tab reconciling planned vs actual by ledger category with per-expense overrides. NEW keeps a minimal skeleton: title + artist string + contingency, six amount-only sections, the three statuses, and a single whole-artist "actual" number.

## 2. Route & permissions

- OLD: two routes — `/budget` (index) + `/budget/:id` (detail) (boom App.jsx:190-191); server router gated by `auth` only (budgets.js:26) — any signed-in user.
- NEW: one route `/recording-budgets` behind `AdminRoute` (cadence App.jsx:173); nav item Approver+ (Layout.jsx:291); server `authMiddleware, withTenant, requireApprover` (recording-budgets.js:11). Tightened gating + tenancy = **intentional divergence**; the loss of the second ROUTE is not (DEF-RBUD-01).

## 5. Behavior/interactions diff

- **Blank-create → detail flow (DEF-RBUD-02).** OLD's New budget requires zero input — the server accepts an all-optional row (budgets.js:208-234) and the client immediately navigates to the editable detail, where the header grid IS the form. NEW inverted this: an inline pre-form demanding a Title (a concept OLD's schema doesn't contain — OLD identity is artist+project), and once created nothing in the header can ever be changed from the UI (DEF-RBUD-12) even though `PATCH /:id` exists (recording-budgets.js:66-80).
- **Artist identity (DEF-RBUD-08).** OLD's ArtistPicker commits either `artist_id` (roster row → freeform cleared) or `artist_name` (freeform → id cleared), with full keyboard support and a no-matches hint (BudgetDetail.jsx:320-465). NEW takes a plain string at create; no roster link, no `artist_id`, so renaming a roster artist silently orphans the budget's actuals match.
- **qty × unit_price (DEF-RBUD-16).** OLD line items are quantity-driven — the server computes `amount = qty × unit_price` on create AND update (budgets.js:385, :431), the add/edit rows show a live computed total, and each section's column headers rename to the template's vocabulary. NEW stores a single typed amount; the structure of the source Excel templates ("10 tracks × $1,500") is unrepresentable.
- **Lifecycle safety.** OLD: distinct confirms; approve keeps items editable "until locked" (both sides match here — NEW also allows item edits while approved); locked blocks header PUT (403), item writes (403), and DELETE (403), and offers Unlock. NEW: no confirms (DEF-RBUD-15); locked blocks PATCH + item writes (parity, :71, :110) but **not DELETE** (:99-102), and the client renders no way out of locked (DEF-RBUD-13) while still rendering the delete button — so the one mutation a frozen budget accepts is destruction (DEF-RBUD-14). NEW's reopen (`status:'draft'`) also leaves `approved_by/approved_at/locked_at` stamps in place (:91) where OLD nulls them (:352-358) — DEF-RBUD-31.
- **Actuals math (DEF-RBUD-20/21).** OLD scopes actuals to the budget's artist (`LOWER(TRIM())`), optionally to its release, groups by ledger category with per-expense override, and converts at the **locked** row rate (`amount / fx_rate_to_usd`, budgets.js:519). NEW's `actual` is the artist's entire approved ledger spend across all categories and all time (recording-budgets.js:24-30), converted with date-based `toUSD` that ignores the locked `fx_rate_to_usd` — contradicting cadence's own `lib/usd.js` "locked rate ALWAYS wins" invariant (the 2026-08-27 finance pass fixed exactly this in `financials.js` via `eUsd` but left this router on `toUSD`). The row's red/green variance (`RecordingBudgets.jsx:68,79`) therefore compares a recording-only plan against whole-career spend — always "over" for any active artist.
- **Costs-to-Date reclassification (DEF-RBUD-19).** OLD lets an operator attribute any matched expense to a budget category (`budget_section_override`, validated against the live category table with the falls-open-on-read-failure rule, budgets.js:63-75) — the mechanism that makes planned-vs-spent comparable. Absent in NEW (column + endpoint + UI).
- **List freshness (DEF-RBUD-30).** OLD touches the parent's `updated_at` on every item write so active budgets float to the top of the `updated_at DESC` index; NEW has no `updated_at` and orders by `created_at`.
- **Shared draft state (DEF-RBUD-32).** NEW keeps ONE `item` form state for all budgets (:21) — values typed into one budget's add-row persist into every other budget's form. OLD scopes drafts per SectionCard.
- **Line-item delete confirm (DEF-RBUD-28).** OLD: `Delete "<description>"?`; NEW deletes immediately (:40).
