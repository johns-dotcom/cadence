### Present in OLD, missing in NEW
- **Unified bank view** (`/bk/vendors/unified`, B:4882; U throughout): one row per company joining ledger invoices with bank activity through links/aliases/name equality — Invoiced / Bank out / Bank−invoiced delta with wire-fee tolerance ✓ / Open / learned booking category / last activity; **unlinked bank payees queue** with inline Link-to-vendor typeahead (U:466-494). - **`?tab=` worklists** Needs matching / Needs artist / To attach with count badges, explainer bands, `onlySeveral` filter, per-view default sort, URL persistence (U:49-86, :299-323).
- **UNMERGE via `vendor_merge_log`**: every merge records the exact expense/vendor_name/payee_map row ids + whether it created the alias (B:5678-5767); the vendor's Setup tab lists "Merged into this vendor" with per-merge Unmerge reversing **by id**, undone merges staying visible, and a `logged_since` disclosure (B:5796-5868, V:2087-2116). NEW merge writes no log (L:887-907) — irreversible and invisible afterwards; deleting the alias chip erases the only trace (the exact "jacob allen" failure OLD's comment documents, B:5785-5792).
- **Payment-details vault**: encrypted `vendor_payment_details` (account/routing/IBAN via `paymentCrypto`), Admin-gated, **audit row per read**, masked until "Show", missing-key state distinguished from "vendor gave nothing" (B:5881-5924, V:1931-1995). - **Vendor dupe surface** (F: all, + VendorDupeDeck): `/bk/vendor-duplicates` with normalization-exact tier **auto-merged** server-side (throttled 10-min, alias/ack-aware, noise-alias guard, B:5539-5585), fuzzy `candidatePairs`/`scorePair` shared-token blocking (B:5600-5615), tier-ranked output; UI: card list with score%, reason, keeps-this-name highlight, **Swap direction**, **Custom-name merge** (both → typed third spelling, F:84-98), **Alias-only** (record relationship without renaming, F:101-111), **"Not duplicates" ack** persisted + un-ackable (B:5635-5669), **Merge all ≥85%** with preview confirm (F:49-64), keyboard review (F:131-147), and the **review deck** with in-deck undo (F:203-208, V:4500-4506). NEW's nearest surface is DataQuality's vendor tab (name-variant groups + W9-mismatch merge, see `_audit/pages/flags-data-quality.md`) — no scoring, no deck, no direction swap, no custom name, no alias-only, no persistent ack of a specific pair, no merge-all, no auto-merge tier.

NEW: `payee` is PATCH-editable on the ledger entry (L:94-99) but the Vendors surface has no affordance.

### Present in NEW, missing in OLD
- A first-class `vendors` table (email/address/bank/notes/W9 per vendor) with `upsertVendor` — OLD derives everything from `expenses` rows. Mechanism swap; the losses it causes are itemized in §7.
- Drawer contact-details editor (email/address/bank/notes, N:106-112) and vendor-record W9 slot independent of any expense (L:813-824).
- `logActivity` entries for W9 upload / rename / merge / batch scan (L:818, :878, :901, :960) — OLD used its own `logBkAction` audit, so this is parity-by-different-log, except OLD also audited alias/email mutations and payment-detail READS, which NEW does not.
- Empty-state card; toasts instead of `alert()`.

### Behaves differently
- **Scan-all-W9s**: OLD scans only unscanned payees, 10 per click, 200ms apart, returns `{scanned, remaining}` (B:5141-5197). NEW rescans **every** W9-bearing payee in one request, serially, unbounded, returning per-vendor discrepancy flags (L:941-961) — a large tenant will hit request timeout and re-bill AI for already-scanned vendors. NEW also never scans a W9 uploaded through the drawer (`vendors.w9_r2_key` — the scan query reads `expenses` only, L:942-946), while the button's visibility condition (`v.w9_on_file`, N:221) *includes* those vendors.
- **Merge/rename email carry**: OLD deletes would-collide rows first, then re-points (B:5223-5234). NEW runs a single UPDATE with `.catch(() => {})` (L:877, :900) — one duplicate address aborts the whole statement and **every** saved email silently stays under the dead name.
- **Merge/rename vendor record**: NEW `DELETE FROM vendors WHERE name = from` (L:867, :894) discards the source's W9 file/contact/notes even when the target record has none. OLD had no vendor record to lose; W9s traveled with the renamed expense rows.
- **Rename result**: OLD returns `updated` count and also renames `vendor_name` (B:5210-5218); NEW returns the count but the client doesn't show it, and `vendor_name` on expenses is untouched (L:863).
- **Detail invoice list**: OLD approved-only, family-grouped, alias-aware W9 canonical (`w9_entry_id || id`, B:5938-5951); NEW lists every non-deleted status flat (L:783-788).

## 5. Data layer differences

- Grouping key: both group by exact `payee` (OLD `TRIM(payee)` in dupes, raw payee in list; NEW `GROUP BY payee` L:758 with a case-insensitive join to `vendors`). Neither folds aliases into the list rollup, but OLD surfaces aliases alongside; NEW's case-SENSITIVE `GROUP BY payee` can emit "Acme"/"ACME" as two rows while its own detail/merge/rename routes match `LOWER(payee)` — the auto-merge tier that would collapse those in OLD (B:5541-5585) has no NEW counterpart.
- OLD list excludes voided (`voided = false OR voided IS NULL`, B:5083); NEW /vendors and /vendor-suggest have **no voided filter** (L:755, :838) even though cadence has void/unvoid (L:1666-1697) and excludes voided everywhere else (L:531, :1476, :1892).
- OLD `invoice_count` counts families (`parent_id IS NULL`, B:5070); NEW counts every approved row incl. split children (L:748). NEW split semantics carve the parent's amount (L:1114-1121), so `total_spent` is correct but the count inflates per split.
- OLD exposes `total_spent_usd` + `currency_count` (B:5072-5073) so mixed-currency vendors are detectable; NEW sums `amount` across currencies into one number rendered as `$…` (L:749, N:274-275).
- Creator-row exclusion: parity — OLD `excludeCreatorRows` (B:5090), NEW `entry_source IS DISTINCT FROM 'creator_payment'` (L:757, :840; 2026-08-27 build).
- Tables: NEW adds `vendors`; `vendor_aliases` NEW is `(label_id, canonical, alias)` w/ unique `(label_id, LOWER(alias))` vs OLD `(primary_name, alias)` unique(alias) **case-sensitive** — NEW's is the sounder constraint. `vendor_emails` NEW keyed `(label_id, vendor, email, label_text)` w/ upsert; OLD `(vendor_name, email, label)` w/ 409. OLD-only: `vendor_merge_log`, `vendor_payment_details` (encrypted), `statement_flag_acks` (`vdup:` fingerprints), `statement_payee_map` repointing inside merge. Label scoping on every NEW query — [INT].
- ZIP: OLD selects roots with computed `family_amount` and orders ASC (B:13175-13193); NEW selects roots only and its xlsx sums raw `e.amount` (L:1917-1925) — under NEW's carve-out splits the child slices are **omitted from the export entirely** (not listed, not in TOTAL). NEW xlsx header fill is hardcoded indigo `FF4F46E5` (L:1914) rather than the workspace accent.
