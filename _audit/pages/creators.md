## 2. Summary

NEW is a faithful compact port of the whole model: three tabs over one dataset, `entry_source='creator_payment'` as the single distinguishing column, REQUIRED_FIELDS gate on the server mirrored client-side, paidState default-Paid with date-moves-with-status, batch = N separate rows all-or-nothing, per-creator per-YEAR W9 exposure, and the convertible/convert/unconvert flow with audit-backed exact-source restore. The core invariants survive: `isCreatorRow` inclusion by equality / exclusion by `IS DISTINCT FROM` (ledgerSource.js:18-20), rounding at the row via `rowUsd2`, leaf-rows-only convertible query, relabel-matches-to-'creator' on convert, vendors/vendor-suggest exclusions. The one substantive regression is **unconvert resetting `match_method` 'creator'→'manual'** (OLD leaves it 'creator'), which promotes an undocumented row's bank match into the invoice-backed bucket — the exact claim the 'creator' disposition exists to never make. The rest is trimming: the move-in tab lost its explanatory summary (convert/review values, already-matched count, universal-gaps collapsed banner), the directory lost Socials/last-payment, search was demoted to client-side with the running total hidden, and several small server refinements (in-flight guard, dry-run detail, footer total) were dropped. Totals: **17 defects (0 P0 · 0 P1 · 1 P2 · 8 P3 · 8 P4), 8 intentional divergences.**

## 4. Interaction & behavior parity

- **Mark-paid local patch** — parity: NEW patches the row in place and never refetches, same rationale comment (Creators.jsx:58-70 vs BkCreators.jsx:161-165). NEW uses the server-returned `payment_status`; but no `payingId` in-flight disable (DEF-CRE-11).
- **Quiet undo** — parity: paid rows get a low-contrast "undo"; unpaid get the prominent action (Creators.jsx:156-158 vs BkCreators.jsx:297-308).
- **gapsFor client mirror** — parity in coverage (7 fields, positive amount, parsed socials); NEW adds an email regex the server also enforces (Creators.jsx:25, creators.js:39) — stricter than OLD's non-empty test (boom creators.js:499). Wordings differ ("creator name" vs "a creator name").
- **Batch** — parity on all four contracts: separate rows never a split family, all-rows-validated-before-any-write, per-row artist/song/currency/payment overrides over batch defaults (cadence creators.js:211-216 merged spread ≈ boom :332-348), deal-name removed on both sides. NEW adds a 1–100 cap (:203) and an activity-bot event (:223). NEW achieves per-row artist/song via **header defaults applied at submit** (Creators.jsx:250) instead of OLD's carry-forward-from-previous-row on "Add another creator" (BkCreators.jsx:580-587) — equivalent for the common case, weaker for multi-song batches (DEF-CRE-14).
- **Pre-select convert-only** — parity at first render (Creators.jsx:211 filters `proposed==='convert'`), but the Set is a `useState` initializer that never re-derives when `rows` reloads after a convert — OLD rebuilds `picked` on every `load()` (BkCreators.jsx:75). Stale ghost ids inflate the "Move N in" count (DEF-CRE-06).
- **Convert / unconvert** — convert audits old `entry_source` per row before the write, updates source + `COALESCE(payment_method,'PayPal')`, relabels live bank matches to 'creator', all inside a transaction with `FOR UPDATE` (cadence creators.js:334-361) — stronger than OLD's untransacted sequence (boom :620-640). Relabel predicate differs (`IS DISTINCT FROM 'created'` vs OLD's `!== 'creator'`, boom :609) — vacuous in practice since SOURCE_PAGES rows are never 'created', and re-writing 'creator' is idempotent. Unconvert restores the **exact** original source from `bk_audit_log` (cadence :380-390 ≈ boom :660-670) — parity — but then resets `match_method` 'creator'→'manual' (DEF-CRE-01).
- **Delete** — parity: soft delete, confirm names amount + creator (Creators.jsx:72); NEW phrases the amount in original currency vs OLD's USD-calc (DEF-CRE-12).
- **Search** — OLD refetches server-side per keystroke (`q` in load deps, boom :63,:81, searching payee/email/paypal/song/artist); NEW fetches once (LIMIT 1000) and filters client-side over the same fields (Creators.jsx:77-85). The server `?q` exists (cadence :73-75, missing vendor_email) but is never called (DEF-CRE-07).

## 5. Server/data parity

- **List endpoint** — column set parity including the load-bearing `payment_status` (both sides carry the "omitting it rendered every paid row Unpaid" comment: cadence :61-62, boom :111-117). NEW adds `is_bulk_deal`, `w9_r2_key`, bank-evidence via per-label accounts. Rounding: OLD sums raw then rounds once (boom :128, with the $0.01 tie-out war story); NEW sums row-rounded values (cadence :90-93) — consistent with cadence's own round-at-the-row convention but a documented OLD divergence (DEF-CRE-08).
- **Directory** — per-creator per-YEAR aggregation with the pg-Date `yearOf` guard on both sides (cadence :112-116 ≈ boom :56-60); first-non-empty-wins contact merge — parity. W9 sharing: OLD = any row of the same payee has `w9_r2_key OR w9_filename` (boom :146,169); NEW = same-payee `w9_r2_key` **plus cross-payee sharing via lowercased email** (cadence :118-119,135) — broader (INT), but drops the `w9_filename` leg it still SELECTs (DEF-CRE-09). Threshold: OLD fixed $600; NEW `reportingThresholdFor(year)` — $600 through 2025, $2,000 from 2026 (OBBBA), shared with the 1099 report (ledgerSource.js:41, ledger.js:1898) (INT). NEW counts only `payment_status='Paid'` rows toward yearly exposure with invoice_date fallback (cadence :131-133); OLD counted all rows by payment_date — effectively equivalent since OLD's unpaid rows have no date and land in the excluded 'undated' bucket; only Paid-but-undated rows differ (NEW buckets them by invoice year — arguably more correct). NEW drops `last_payment`, `social_handles`, per-creator `by_year` map exposure and doesn't sort `artists` (boom :191).
- **paidState resolver** — parity: Paid default, explicit `Unpaid`/`paid:false` clears the date, Paid without date gets today (cadence :50-54 ≈ boom :233-240). NEW additionally stamps `paid_by`/`paid_marked_at` and fires `stampFxRateAsync` on Paid, clears them + `fx_rate_to_usd` on Unpaid (cadence :171-181, :252-258) (INT — cadence fx model).
- **PUT whitelist** — parity on the payment_status/payment_date move-together block outside the loop (cadence :241-262 ≈ boom :382-398) and on entry_source being non-editable. NEW whitelist omits `ufr` and `fx_rate_to_usd` (fx deliberate; `ufr` DEF-CRE-17).
- **Convertible** — leaf-rows-only subquery, `already_matched` via live bank match, `review_reasons` (category test + $5k cap) vs `missing_info` advisory — all parity (cadence :291-327 ≈ boom :532-582). NEW returns **no `summary`** object (DEF-CRE-04), caps at 500, orders by created_at. Convert-eligible categories are data-driven (`categories.ui_group='campaign'`, fallback marketing/pr) vs OLD's hardcoded `['Marketing','Advertisements']` (INT). SOURCE_PAGES uses cadence's `'recoupment'` spelling (INT).
- **Exclusion wiring** — NEW excludes creator rows from the vendors directory derivation (ledger.js:757), vendor-suggest (:840) and — beyond OLD — the payments queue (:533). OLD's queue **includes** creator payments (bookkeeping.js:6010 excludes only recoupments/artist_campaigns/bank_statement), so in NEW an Unpaid creator payment is invisible on /payments (DEF-CRE-05). OLD also excludes creators from `/w9s` (bookkeeping.js:8012) and global search payees (boom search.js:127); NEW's scan-w9s vendor sweep does not exclude them (ledger.js:941-945, DEF-CRE-16) and NEW's 1099 report deliberately includes them (ledger.js:1885-1900, shared threshold per ledgerSource.js:38-41 — INT). `movedMatchMethodSql` guard on match-moving call sites is ported (bank-statements.js:551,767) and ingest re-labels an auto-match onto a creator row (:124) — parity with OLD's sweep contract.

## 7. Intentional divergences

- Tenancy: `label_id` on every query, `withTenant`, per-label bank-accounts for evidence cols; `logActivity` + activity-bot batch event (creators.js:222-223).
- OBBBA year-dependent 1099 threshold (`reportingThresholdFor`: $600→$2,000 from TY2026) + `threshold_note`, shared with the vendor 1099 report — supersedes OLD's fixed $600 (ledgerSource.js:38-41).
- W9 shared across payees via lowercased `vendor_email` (cadence creators.js:118-119) — broader than OLD's payee-only sharing.
- Convert-eligible categories data-driven from per-label `categories` (`ui_group='campaign'`) vs OLD's hardcoded list; SOURCE_PAGES spelled `'recoupment'` per cadence's entry_source vocabulary.
- FX stamping model: `stampFxRateAsync` on Paid, cleared on Unpaid; body-supplied `fx_rate_to_usd` no longer accepted.
- Convert runs in a transaction with `FOR UPDATE`; batch caps at 100 rows; email format validated server-side (stricter than OLD).
- NEW app chrome: toasts, Skeleton loader, error card with Retry, "L" ledger `?focus` deep-link, directory row-click→payments filter.
- 1099 report includes creator rows by design (creators genuinely need 1099s; threshold helper shared so the two surfaces agree).
